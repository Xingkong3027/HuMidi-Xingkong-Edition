## 下载与运行要求

从[本仓库 Releases](https://github.com/Xingkong3027/HuMidi-Xingkong-Edition/releases/latest)下载，普通使用者选择 EXE：

| 附件 | 用途 |
| --- | --- |
| `HuMidi-Xingkong-Edition-2.1.2-xk.15-Windows-x64.exe` | 直接运行的 Windows x64 单文件程序。 |
| `HuMidi-Xingkong-Edition-2.1.2-xk.15-Source.zip` | 此本地版本对应的完整源码，用于阅读、修改和自行构建。 |
| `HuMidi-Xingkong-Edition-2.1.2-xk.15-Licenses.zip` | 软件、依赖及模型相关声明和许可证文本。 |
| `SHA256SUMS.txt`、`*.exe.sha256` | 检查附件完整性的 SHA-256 校验值。 |

运行目标为 **Windows 10/11 x64**，需要 **Microsoft Edge WebView2 Runtime**，以及支持键盘输入的 Roblox 钢琴体验。EXE 内嵌界面、图标与 PedalAI 模型，无需安装 Python、Node.js 或 Rust，也不需要把模型文件放在旁边。单文件程序不包含 WebView2 运行时；其[官方下载入口](https://developer.microsoft.com/en-us/microsoft-edge/webview2/)提供安装选项。

本分支当前没有提供经过验证的 macOS / Linux 发行包。公开 EXE 未进行代码签名，Windows 可能显示未知发布者；请核对下载来源和校验值。

## 快速开始

1. 启动 EXE，在“设置 → 显示”选择中文、English 或跟随系统。
2. 在演奏页导入 MIDI，或者从歌单页点击“导入 MIDI 并设置”。单首可选择音轨与左右手；多首可自动处理或逐首选择。
3. 核对速度、移调、键盘布局、踏板、倒计时及模拟演奏参数。第一次试用可先保留默认值。
4. 如需长期保存，命名后加入歌单。已有歌曲使用编辑入口修改并保存，无需重新导入原件。
5. 在 Roblox 中进入钢琴交互状态，使钢琴输入区域准备好接收键盘输入。
6. 点击播放并在倒计时内切到游戏，或开启[自动切换 Roblox](#roblox-窗口焦点选项)。默认 **F6 播放/暂停，F7 停止**。
7. 切换输入目标前停止演奏。程序通过前台键盘输入演奏，不会直接向游戏发送音频；实际发声由目标钢琴决定。

## MIDI 导入与演奏设置

支持单个或多个 `.mid` / `.midi`。钢琴 MIDI 通常更适合直接演奏；多乐器 MIDI 应先检查选轨，避免把鼓或其他不需要的声部一起映射为钢琴键。

批量导入可以自动选择可播放轨道，也可为每个文件手动指定轨道和左右手。查看最终成功/失败结果；某首失败时，先检查该文件及其提示。曲目加入歌单后保留各自设置，不会因为打开另一首就统一覆盖。

| 设置 | 说明 |
| --- | --- |
| 播放速度 | 界面以百分比表示，`100%` 为原速，`50%` 为半速；目标 BPM 按原速比例换算。 |
| 移调 | 调整音高；需与目标钢琴可用键域一起检查。 |
| 88 键布局 | 仅在目标钢琴支持对应布局时开启，普通布局和 88 键布局不可混用。 |
| 开始前倒计时 | 可关闭或设为 1–10 秒；每首歌单歌曲可分别保存。 |
| 密集 MIDI 性能优化 | 默认关闭，按歌曲保存；仅主动开启时使用额外的密集谱与 AI 加速路径。 |

### 非破坏性裁剪

“曲目裁剪”只改变本次编译和播放范围，不覆盖 MIDI 原件。

- **自动移除首尾空白**：根据当前所选音轨的可播放音符确定范围，每首独立计算。
- **手动范围**：关闭自动模式，填写开始与结束秒数；结束为 `0` 表示曲尾，其他结束值必须大于开始值。
- 时间按**当前速度下的播放秒数**计算。修改速度后应重新核对手动范围。
- 保留范围从新的零点开始播放；跨边界音符会截取到范围内。裁剪设置随歌曲保存，仍可另存原始 MIDI。

### 密集 MIDI 优化的适用范围

开启后会使用额外计算优化，并合并同一时刻重复的相同物理按键，可能产生细微演奏差异。一般歌曲已经正常时可保持关闭。

关闭它不等于本分支所有行为都与原版完全相同：导入前置校验、非法 MIDI 修复确认、模拟演奏策略、缓存和停止清理仍有分支差异。当前使用 Rust 键盘输出实现，旧说明中的 Python / `pynput` 后端已不适用于本版。

## 踏板与 PedalAI

支持无踏板、PedalAI 及 Adaptive、Rhythmic、Harmonic 等策略，并可使用 MIDI 自带踏板数据。请按歌曲和目标钢琴调整，不要把“使用原始 MIDI 踏板”理解为所有文件都含有效踏板事件。

PedalAI 已整合上游 2.1.2 的模型与起音特征，提供：

- **自动峰值**：分析 AI 置信度峰值，图中的阴影显示实际踏板区间。
- **自定义阈值**：分别调整按下和抬起阈值曲线，细调持踏范围。
- 生成/重新生成、持踏时长与切换频率统计，以及频繁或过长持踏提示。

旧歌曲已有的有效自定义曲线会保留。新模型可能改变相同阈值下的效果；是否听起来合适仍需在目标钢琴中试听。模型及训练数据署名见[第三方声明](THIRD_PARTY_NOTICES.md)和程序许可页面。

## 模拟人演奏与随机种子

配置来源可选“禁用”“使用全局配置”或“单独配置当前曲目”。全局参数位于“设置 → 演奏预设”，采用全局配置的歌曲在下次编译时使用它；独立配置保留自己的值。

细节包括双手处理、和弦轻微错开、时序和音符时长变化、漂移校正、错音、速度起伏等。可按需要逐项启用，不必一次全部开启。

| 随机策略 | 行为 |
| --- | --- |
| 动态 · 每次重新演奏 | 启用需要随机数的效果时，每次重新生成；没有随机效果时可复用有效缓存。 |
| 固定 · 自动生成种子 | 保存自动生成的种子；主动修改相关演奏参数会更新自动种子，也可点击“换一个”。 |
| 固定 · 自定义种子 | 自行输入种子，用于重复比较；需要相同源码版本、原始音符和全部有效设置。 |

加载歌曲不会擅自更换已保存的固定种子。Python 与 Rust 的随机算法不同，固定种子也不能保证跨架构逐音一致。比较不同导入入口时，要同时核对全局预设、种子、音轨、踏板和裁剪，而不只是速度。

## 高级歌单与批量操作

MIDI 歌曲保留原件副本、来源、选轨及左右手、速度、移调、布局、踏板、倒计时、裁剪和模拟演奏设置，以及可用的编译缓存。文本曲谱也可命名保存、继续编辑和导出。

### 选择、编辑与排序

- 普通点击选中歌曲；**Ctrl+点击**多选/取消，**Shift+点击**连选，也支持 Ctrl 扫选。
- 歌单页 **Ctrl+A** 或右下角“全选”会选择**整个歌库，包括被搜索隐藏的歌曲**。搜索框及其他编辑框中的 Ctrl+A 仍用于选择文字；弹窗与原生文件选择器不会改变歌曲选择。
- 清空搜索后，拖动已选歌曲可将整组移动到插入位置。搜索与来源显示方便定位曲目。
- 通过右侧操作区或歌曲菜单播放、编辑、重命名、另存原始 MIDI、批量修改或删除。
- **批量修改只应用勾选的字段**，其余设置保留；MIDI 专用操作不适用于纯文本曲谱。
- 导入后可在后台准备缓存，进度区域保持固定占位，避免列表反复上下跳动。

### 五种播放模式

| 模式 | 行为 |
| --- | --- |
| 单曲播放 | 播放当前歌曲，结束后不自动继续。 |
| 单曲循环 | 自然结束后重新播放当前歌曲。 |
| 顺序播放 | 按歌单顺序播放，到末尾停止。 |
| 列表循环 | 按顺序播放，末尾回到开头。 |
| 随机播放 | 自然结束后按随机模式选择后续歌曲。 |

主控制区和紧凑模式均有上一首/下一首。**只有自然结束触发歌单推进**；手动停止、取消倒计时或替换播放来源会取消自动推进。焦点暂停和窗口切换失败不算歌曲自然结束。

## 新旧歌单导入与备份

### 已有导出的歌单文件

选择 **歌单 → 导入歌单 → 选择新旧版歌单文件（推荐）**，直接打开 `.humidiplaylist`、`.json` 或 ZIP 完整包，**无需解压，也无需选择文件夹**。按文件内容识别历史兼容格式；旧歌库的 `index.json` 也可从此入口选择。

### 只有旧程序本地歌库

使用“读取本地歌库文件夹”，选择旧数据目录或其中含 `index.json` 的 `playlist` 文件夹。这是没有导出包时的备用方式，才会显示目录选择器。程序复制歌曲、原始 MIDI 和可用缓存，不覆盖旧目录；启动新版不会自动合并所有旧库。

### 导出方式

| 方式 | 内容与用途 |
| --- | --- |
| 普通歌单 | 保存歌曲设置与来源，文件较小；MIDI 歌曲可能依赖原电脑路径。文本和只有缓存的歌曲可自包含。 |
| 完整包（推荐） | 携带原始 MIDI、文本及可用缓存，适合备份、迁移和换电脑。 |

只有旧缓存而没有原件时，可恢复旧结果，但无法重新编辑依赖原始音符的参数，也不能保证等同于新版重新解析。旧普通包的路径失效且无有效缓存时，需要补回原件。新格式向后兼容读取旧包，不代表旧程序能读取全部新字段。

本版包含历史速度单位和缺失/null 踏板曲线修复，可读取此前受影响的歌曲。若曾用错误速度编辑后另存，建议保留原始包并从它重新导入。完整步骤见[迁移指南](docs/MIGRATION.md)。

## 全局演奏设置

演奏页现在有“独立设置”“模拟人演奏”“全局设置”三个标签。未加载曲目时，独立设置显示“新曲目默认值”，仅影响以后导入；编辑歌曲时显示当前曲目范围。模拟人演奏的全局预设仍可按歌曲选择，与这里的全局运行行为不同。

以下五项自动保存为程序设置，不再跟随每首 MIDI、文本曲谱或缓存保存，也不通过歌单批量修改：

| 全局选项 | 用途 |
| --- | --- |
| 开始时释放空格（踏板） | 开始输出前释放一次踏板，不关闭后续踏板事件。默认关闭。 |
| 单曲试听结束后停留在曲尾 | 原“播放完毕保留暂停位置”。默认开启；曲尾暂停，可拖回某段继续，直接播放从头开始。歌单仍按播放模式推进。 |
| 调试输出 | 默认关闭。开启时在调试页记录会话使用的全局开关，不改变音符、踏板或时序。 |
| 播放时自动切换到 Roblox 窗口 | 默认关闭，具体联动见下节。 |
| 本窗口获得焦点时暂停演奏 | 默认关闭，具体联动见下节。 |

修改在**下次开始演奏**时生效，无需重新导入；当前会话和暂停后继续沿用该会话开始时的设置。旧版本的三个逐曲开关从原新曲目默认配置接续为全局值，已有明确全局值优先；旧歌单或演奏存档中的同名字段不再覆盖它们。新导出包不携带这些运行开关。

## Roblox 窗口焦点选项

位于 **演奏 → 全局设置 → 窗口焦点**，原程序设置中的重复入口已移除。两个开关均为**默认关闭**，已明确保存的用户选择会保留。

| 自动切换 Roblox | 本窗口获得焦点时暂停 | 行为 |
| --- | --- | --- |
| 关闭 | 关闭 | 手动切换目标；回到本程序时进度继续，本程序不接收演奏按键。 |
| 关闭 | 开启 | 倒计时后仍在本程序，或演奏中切回本程序时暂停；切到目标后用播放快捷键继续。 |
| 开启 | 关闭 | 每次开始或手动继续时尝试切到 Roblox；演奏中切回程序不自动暂停，仍抑制发给自身的按键。 |
| 开启 | 开启 | 先确认 Roblox 获得焦点，再检查暂停条件；演奏中主动切回程序会暂停，手动继续时再次尝试切换。 |

自动切换在倒计时后、音符输出前尝试一次，等待期间不消耗歌曲时间；新歌开始也会尝试。它识别 Roblox Player 游戏进程，排除浏览器、Studio 和启动器，可请求恢复最小化窗口。**不会替你进入游戏钢琴交互区域，也不会在演奏中循环抢回焦点。**

找不到游戏或 Windows 未允许切换时，会保持暂停并说明原因；准备好目标后可用播放快捷键重试。停止会取消等待。真实系统前台限制与具体游戏收键仍需实机确认。

xk.14 同时包含 xk.13 的踏板空格误触控制按钮修复：鼠标点击下一首等按钮后，不会因演奏踏板空格再次激活按钮而连续切歌。主动使用 Tab/空格操作按钮仍被保留。无论两个开关如何设置，程序都抑制向自身前台窗口发送演奏按键；它不是对所有其他应用的输入保护开关。

## 文本曲谱转换

在转换页粘贴 **Virtual Piano** 文本曲谱，选择 BPM 和是否模拟演奏后，可直接播放，或命名加入歌单。歌单里的文本曲目可修改内容；转换页也提供基于当前音符的文本导出。文本和 MIDI 的表达能力不同，不应把文本往返视为原 MIDI 的无损转换。

## 快捷键与界面

| 默认按键 | 操作与范围 |
| --- | --- |
| F6 | 全局播放/暂停。 |
| F7 | 全局停止。 |
| 上一首 / 下一首 | 默认未绑定，可在设置中分别配置。 |
| Ctrl+A | 歌单页全选整个歌库；编辑框内选择文字。 |
| Ctrl+S | 保存当前曲目到歌单；可在“设置 → 快捷键 → 保存演奏”查看/修改绑定。 |
| Ctrl+K | 切换紧凑模式。 |

“设置 → 快捷键”为播放/暂停、停止、上一首、下一首各提供两个绑定槽，支持功能键、组合键和受支持的媒体键；录入时按 Esc 取消，重复绑定会从原位置移除。

显示设置支持跟随系统/简体中文/English、主题、自定义主题、窗口透明度、置顶、钢琴与时间轴、踏板显示及播放时切换可视化。紧凑模式保留歌曲与播放模式选择、上一首/下一首；小窗口页面支持滚动。

## 数据位置与更新

默认数据目录为 `%USERPROFILE%\.humidi-xingkong-v2`，用于配置、主题、歌单和默认演奏存档。存档、MIDI 默认目录及主题位置可在“设置 → 文件”查看或调整。它与上游及旧 Python 星空版目录分开，不会自动删除或合并旧数据。

程序检查的是**本分支** GitHub Releases，发现更新后可前往发行页下载，不会静默替换正在运行的 EXE。升级前建议导出完整歌单备份；只替换程序文件，不要把源码 ZIP 当作歌单导入。

## 兼容性与常见问题

**为何出现非标准 MIDI 修复确认？** 正常文件先按正常路径导入。检测到特定的非法通道数据字节时，才询问是否兼容修复；许可按曲目保存，只处理导入数据，不改原件。真正截断或结构损坏的文件不保证能修复。完整音轨后的零填充不应误报 `Truncated MIDI chunk header`，本版已修复此问题。

**导入旧歌单为什么看不到文件？** 应使用推荐的“选择新旧版歌单文件”；“读取本地歌库文件夹”只用于目录迁移。不要改扩展名来代替格式兼容处理。

**为什么正常包导入后还需要处理，或更换电脑不能播放？** 普通包可能只保存原件路径，缓存缺失时会重新编译。路径失效需要原件；换电脑优先用完整包。只有旧缓存的曲目存在重新编辑限制。

**从歌单导入与直接 MIDI 导入会不会演奏不同？** 带相同原件、相同全部有效设置的已测旧完整包、新普通包和新完整包，与直接导入的最终音符、合并事件及记录按键一致。动态随机、不同全局预设、模型版本、缓存来源都会影响比较；不能推广为所有历史缓存或所有原版行为完全相同。

**焦点切换后暂停或没有声音？** 在“演奏 → 全局设置”检查上面的两个窗口选项，以及游戏钢琴是否已进入交互状态。自动切换只负责窗口，不能保证游戏已接收输入；本程序自身不合成钢琴声音。

**可以保证整夜挂机或所有 Roblox 钢琴都正常吗？** 自动化覆盖了导入、演奏事件和焦点状态模拟，没有完成真实游戏按键注入、所有体验兼容性或整夜挂机验证。完整范围和例外见[验证说明](docs/VALIDATION.md)。
