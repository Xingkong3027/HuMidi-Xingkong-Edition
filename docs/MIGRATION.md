# 旧歌单迁移与备份

适用版本：2.1.2-xk.14。

## 有导出的歌单文件

1. 打开歌单页，点击“导入歌单”。
2. 点击“选择新旧版歌单文件（推荐）”。这是文件选择器。
3. 选择 `.humidiplaylist`、`.json` 或 ZIP 完整包，直接导入，无需解包。支持的 JSON / ZIP 与历史格式按内容识别，并不只依赖扩展名。
4. 等待导入和后台处理完成。检查歌曲数量、速度、选轨和踏板等设置后播放。

旧 Python 导出的普通包或完整包都用这个入口。也可以直接选择旧歌库的 `index.json`。

## 只有旧程序的本地数据

点击“读取本地歌库文件夹”，选择旧数据目录或其中的 `playlist` 文件夹。程序寻找 `index.json` 并复制曲目、原始 MIDI 和可用缓存。此入口只用于目录，不能在其中选择导出的歌单文件。

原目录和原始导出文件保留不动。新版本使用独立的 `%USERPROFILE%/.humidi-xingkong-v2` 数据目录；不会仅因启动新版本就自动迁移全部旧 Python 歌库。

## 普通包和完整包

| 方式 | 用途与限制 |
| --- | --- |
| 普通歌单 | 保存设置和来源；MIDI 歌曲可能依赖原电脑的原件路径。文本及只有缓存的歌曲可自包含。 |
| 完整包 | 携带 MIDI 原件、文本和缓存，适合备份及换电脑。 |
| 本地目录迁移 | 没有导出包时读取旧本机歌库。 |

优先备份完整包。旧普通包的 MIDI 路径失效且没有有效缓存时，需要原件才能重新生成。只有旧事件缓存的歌曲可以恢复原结果，但不能重新编辑需要原始音符的参数，也不能保证与新版本从 MIDI 重新计算逐项相同。

本版能读取历史格式，不代表旧版程序能读取本版导出的所有新字段或单位标记；请保留旧备份。

## 旧版导入问题

xk.10 已修正历史速度单位；xk.11 又修正后台处理把缺失踏板曲线写成 null 的问题。已受 null 曲线影响的歌曲可由本版直接读取，后续保存或生成缓存会写回有效数组。

若歌曲曾以错误速度编辑并另存，旧来源特征可能丢失；无法可靠识别时，不会把所有高倍率都强行改成百分比。保留原始包，并从原始包重新导入恢复。

## 比较两种入口的演奏

必须核对原始 MIDI、音轨与左右手、速度、移调、裁剪、键盘布局、踏板模式及曲线、模拟演奏模式、全局预设、随机种子、密集优化开关。需要重复结果时使用固定种子；“每次随机”会重新生成。

测试范围及旧缓存的例外见 [VALIDATION.md](VALIDATION.md)。
